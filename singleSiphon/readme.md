
# singleSiphon

A ROS 2 package for keyboard-driven frequency control of two actuators (e.g. peristaltic pumps / siphons) running on an ESP32 via micro-ROS over UDP.

---

## What this directory is

This folder is simultaneously a **colcon workspace** and a **ROS 2 package** — both living at the same root. That's slightly unusual (normally you'd have `workspace/src/package/`) but valid for a single-package repo.

```
~/singleSiphon/          ← colcon workspace root  (you run `colcon build` here)
├── singleSiphon/        ← Python module  (the actual node source code)
├── launch/              ← ROS 2 launch files  (your source)
├── package.xml          ← ROS 2 package manifest  (declares name, deps)
├── setup.py             ← Python package config + entry_points (maps CLI name → Python function)
│
├── build/               ← generated by colcon, safe to delete
├── install/             ← generated by colcon; `source install/setup.bash` activates the package
└── log/                 ← generated by colcon build logs
```

**How colcon uses these pieces:**
- `package.xml` — tells colcon this is a ROS 2 package named `singleSiphon` and what it depends on
- `setup.py` `entry_points` — registers `actuator_teleop` as a shell command that calls `TeleopNode:main`
- `colcon build` compiles everything into `install/`, which is a self-contained overlay you `source` to make `ros2 launch` and `ros2 run` aware of this package
- `build/` and `log/` are just build artifacts — they are not source and can be regenerated

**The short version:** you edit files in `singleSiphon/` and `launch/`, run `colcon build`, source `install/setup.bash`, and then ROS 2 knows about your package.

## Mental Model

```
┌─────────────────────────────────┐        UDP (port 8888)       ┌────────────────────────┐
│         Laptop (ROS 2)          │ ◄──────────────────────────► │   ESP32 (micro-ROS)    │
│                                 │                               │                        │
│  ┌──────────────────────────┐   │   /actuator_1/freq (Float32) │  PWM output → Actuator │
│  │   ActuatorTeleop node    │ ──┼──────────────────────────►   │  PWM output → Actuator │
│  │  (keyboard → freq cmds)  │   │   /actuator_2/freq (Float32) │                        │
│  └──────────────────────────┘   │                               │  Current sense → topic │
│                                 │  ◄── /micro_ros/motor_current │                        │
│  ┌──────────────────────────┐   │                               └────────────────────────┘
│  │   MicroXRCEAgent         │   │
│  │  (micro-ROS ↔ ROS 2 DDS) │   │
│  └──────────────────────────┘   │
└─────────────────────────────────┘
```

**The flow:**
1. You press a key in the `ActuatorTeleop` xterm window.
2. The node publishes a `Float32` frequency (Hz) to `/actuator_1/freq` or `/actuator_2/freq`.
3. The micro-ROS agent on the laptop bridges those topics into the micro-ROS world over UDP.
4. The ESP32 receives the frequency value and drives its PWM output accordingly.
5. The ESP32 publishes motor current back on `/micro_ros/motor_current` for monitoring.

---

## ROS Topics

| Topic | Type | Direction | Description |
|---|---|---|---|
| `/actuator_1/freq` | `std_msgs/Float32` | laptop → ESP32 | Target frequency for actuator 1 (0.0–1.5 Hz) |
| `/actuator_2/freq` | `std_msgs/Float32` | laptop → ESP32 | Target frequency for actuator 2 (0.0–1.5 Hz) |
| `/micro_ros/motor_current` | `std_msgs/Float32` | ESP32 → laptop | Motor current feedback |

QoS: BEST_EFFORT, KEEP_LAST depth 10.

## Keyboard Controls

In the teleop xterm window:

| Key | Action |
|---|---|
| `q` | Actuator 1 frequency +0.1 Hz |
| `a` | Actuator 1 stop (0 Hz) |
| `z` | Actuator 1 frequency −0.1 Hz |
| `r` | Actuator 2 frequency +0.1 Hz |
| `f` | Actuator 2 stop (0 Hz) |
| `v` | Actuator 2 frequency −0.1 Hz |
| `Ctrl+C` | Quit |

Max frequency: 1.5 Hz. Step size: 0.1 Hz.

## Build & Run

```bash
# Build
cd ~/singleSiphon && colcon build --packages-select singleSiphon

# Source
source ~/singleSiphon/install/setup.bash

# Launch (starts micro-ROS agent + teleop node in xterm)
ros2 launch singleSiphon frequencyControlDemo.py
```

The launch file starts two processes:
- **MicroXRCEAgent** — UDP on port 8888, bridges ESP32 ↔ ROS 2
- **actuator_teleop** — opens in an `xterm` window for keyboard input

### Monitor topics

```bash
ros2 topic echo /actuator_1/freq
ros2 topic echo /actuator_2/freq
ros2 topic echo /micro_ros/motor_current
```

## ESP32 Side (not in this repo)

The ESP32 firmware (micro-ROS) needs to:
- Subscribe to `/actuator_1/freq` and `/actuator_2/freq` (`Float32`)
- Drive PWM output based on received frequency
- Publish motor current to `/micro_ros/motor_current`
- Connect to the agent via UDP at the laptop's IP, port 8888
- Bump executor handle count to 3 when the subscriber is added
